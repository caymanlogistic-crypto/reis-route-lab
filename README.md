# Рейс · восстановление маршрутов

Русскоязычное личное рабочее пространство: реестр рейсов, контрольные точки, модель движения и отдыха, неизменяемые версии, XLSX, резервные копии. Расчётные данные явно отделены от исходных отметок.

## Запуск на Windows

Нужен Node.js 24. Дважды щёлкните `Запустить.cmd` или выполните `npm install`, затем `npm start`. Откройте http://127.0.0.1:4317. Окно сервиса должно оставаться открытым. Сервис доступен только этому компьютеру.

Данные хранятся независимо от исходников: `%LOCALAPPDATA%\ReisRouteLab\reis.sqlite`. Путь переопределяется `REIS_DATA_DIR`. Не копируйте открытый файл SQLite отдельно: пользуйтесь резервной копией приложения. Технический статус встроенного Node SQLite — experimental; закреплена проверенная среда Node 24.14.1.

## Начало работы

1. В реестре выберите «Демонстрация» — это пять собственных тестовых опор и синтетическая геометрия, не настоящий дорожный маршрут.
2. Нажмите «Рассчитать». Откройте остановки и проверки; предполагаемые паузы можно изменить, переместить вдоль геометрии, удалить или закрепить, затем пересчитать.
3. Создайте XLSX. Повторное скачивание выдаёт сохранённые байты; новая выгрузка создаёт отдельную запись.
4. Для своего рейса нажмите «Новый рейс», явно выберите режим времени, введите опоры вручную или импортируйте CSV/XLSX с сопоставлением столбцов. Времена и координаты не переставляются автоматически.
5. Результат каждой версии содержит собственный снимок исходников. Изменение черновика делает старый расчёт историческим. Раздел «Версии» позволяет открыть и сравнить результаты.

## Яндекс

`YANDEX_ROUTER_KEY` хранится в окружении; локально разрешён исключённый из Git `.env`. Браузерная карта использует отдельный `YANDEX_MAP_KEY`, ограниченный нужным доменом. Серверный ключ не передаётся браузеру. Настройки содержат проверку подключения и отдельное подтверждение прав на хранение/экспорт по вашему договору.

Проверка 27.10.2026: предоставленный ключ отклонён HTTP Router API и JavaScript Maps v3 с HTTP 403; Router API сообщил `Invalid key`. Поэтому реальная интеграция пока не принята. Без рабочего браузерного ключа показывается явно подписанная схема без географической подложки. Для реальных рейсов нет подмены дороги прямой линией или легковой маршрутизацией.

Маршрутизатор запрашивается `mode=truck`, `traffic=disabled`, без даты из прошлого и без оптимизации порядка. Передаются масса, максимальная масса, нагрузка на ось, высота, ширина, длина и прицеп. Исторические пробки и дорожные лимиты скорости неизвестны. Геометрия и длина маршрутизатора сохраняются раздельно от расстояния модели.

## Хранение и восстановление

Локально SQLite; опубликованная личная версия использует D1 и R2 за входом ChatGPT. Локальные и облачные базы независимы. Для переноса используйте резервную копию JSON из настроек: исходники, версии и сохранённые файлы с SHA256. Секреты не включаются. Восстановление сначала проверяет структуру, связи и содержимое файлов; перед заменой данных создаётся копия текущего состояния. Автоматические копии выполняются при обращении к реестру работающего приложения с настраиваемым интервалом и числом сохранений; выключенный компьютер не выполняет задания. Для больших архивов выше лимита запроса 12 МБ перенос нужно выполнять локальным административным инструментом, которого в этой версии пока нет.

## Проверки

`npm test` — ядро, импорт/экспорт и интеграционные сценарии с реальным SQLite. `npm run build` — единый ESM Worker со встроенным интерфейсом. `npm run validate` — проверка сборки. XLSX дополнительно читается независимым Python openpyxl; если его нет, соответствующая проверка сообщает пропуск. `npm audit` проверяет дерево зависимостей.

## Границы первой версии

Облако ограничивает расчёт примерно 50 000 строк; локально 150 000, один рейс до 31 суток и 50 опор. Можно выбрать шаг 1/5/10/30/60 секунд, для длинных облачных рейсов — 30/60. Выгрузка универсального XLSX не подтверждает импорт Wialon. Поиск грузовых парковок не подключён: предполагаемое место отмечается неизвестной областью. Проверка режима труда по закону не выполняется.

Если привязка дороги отличается от фиксированной опоры более чем на 0,25 м, расчёт сообщает нерешённый подъезд: дорисовывание неподтверждённой дороги запрещено. Приблизительные интервалы времени и выборочная реконструкция пропусков исходной телеметрии пока отклоняются явным конфликтом; исходные записи не переписываются. Географические часовые зоны получаются из приблизительной сетки tz-lookup 6.1.25, допускается явный IANA-пояс; правила даты использует Intl среды исполнения. Точные полигоны границ и предпочтительные часы ночного отдыха ещё требуют развития. Текущая модель тормозит на временных опорах и указывает это допущение.

Актуальные результаты проверки и решения: `docs/STATE.md`, `docs/DECISIONS.md`.
