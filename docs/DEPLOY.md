# GitHub и сервер: только настройки

Репозиторий: https://github.com/caymanlogistic-crypto/reis-route-lab — публичный по прямому указанию владельца. Исходники приложения не изменены при этой настройке.

## Связь

`master` → GitHub Actions `Checks` → `Sync source to SpaceWeb` → SSH → сервер 77.222.40.251, пользователь spugovxsim. После успешных проверок push в master автоматически доставляет архив этого же коммита. Есть также ручной запуск синхронизации из master.

Используются стандартные ubuntu-latest/windows-latest. В публичном репозитории их выполнение бесплатно и не расходует квоту минут для закрытых репозиториев: https://docs.github.com/en/billing/concepts/product-billing/github-actions . Артефакты не загружаются в Actions. npm-кеш остаётся в пределах стандартных правил хранения GitHub.

Секреты лежат в GitHub Environment `hosting`: `HOSTING_SSH_PRIVATE_KEY` и `HOSTING_SSH_KNOWN_HOSTS`. Пароль SSH в workflow не используется. Ключ хоста взят из существующего доверенного подключения с StrictHostKeyChecking. Отдельный ключ Actions ограничен forced command и restrict: он может только принять архив исходников, не выполняет произвольные SSH-команды, не запускает приложение и не открывает туннели. Старые SSH-ключи сохранены; перед добавлением создана копия authorized_keys на сервере.

## Каталоги

Указанный владельцем `/planexp/public_html/reis-route-lab` соответствует `/home/s/spugovxsim/planexp/public_html/reis-route-lab`. Каталог на момент настройки пуст.

Исходники и служебный приёмник размещаются вне веб-каталога: `/home/s/spugovxsim/planexp/reis-route-lab-private/`. Это позволяет не публиковать служебные файлы веб-сервером. `current` указывает на последнюю доставленную версию, `releases/` хранит отдельные версии, `bin/receive.py` — приёмник. `current/hosting-sync.json` содержит SHA коммита, SHA256 архива, UTC-время и явное `runtime: not-deployed`.

Файлы окружения, ключи, базы и локальные данные не включаются в Git и архив. Приёмник ограничивает размер, отклоняет выход за каталог, симлинки, специальные файлы и `.env`; архив не исполняется. Он не меняет соседние сайты, корневой .htaccess, существующие данные и настройки веб-сервера.

## Граница настройки

Подтверждено SSH-проверкой: SpaceWeb shared hosting, Gentoo, glibc 2.21, Node 18.14.2, systemd отсутствует. Провайдер не поддерживает Node-веб-приложения на этой услуге: https://help.sweb.ru/dopolnitel6noe-po-na-serverah-virtual6nogo-hostinga_1208.html . Приложению нужен Node 24. Связь GitHub с сервером означает доставку исходников; это не развёртывание работающего приложения.

По последнему указанию владельца выполняются только настройки. Код приложения, его архитектура и базы не меняются; перенос на VPS, PHP-адаптация и переход на облачную версию не выполняются. Уже опубликованная личная Sites-версия продолжает существовать независимо.

## Проверка и обслуживание

GitHub → Actions: зелёные `Checks` и `Sync source to SpaceWeb`. На сервере обычным административным SSH-доступом: `readlink ~/planexp/reis-route-lab-private/current` и `cat ~/planexp/reis-route-lab-private/current/hosting-sync.json`. SHA должен совпадать с проверенным коммитом GitHub. Тест запретной команды отдельным ключом возвращает `Only sync <commit-sha> is allowed.`

Для замены ключа сначала установить новый ограниченный публичный ключ, обновить секрет `HOSTING_SSH_PRIVATE_KEY`, проверить доставку и только затем удалить старую строку из authorized_keys. Не использовать личный административный ключ в GitHub Actions. История доставленных исходников автоматически не очищается.
